01 — 프로젝트 소개 · OVERVIEW:

찾는 영상과 사진에 더 빨리 닿는 위버스 미디어

세븐틴 커뮤니티의 미디어 탭에서 특정 공연의 사진을 찾고 내려받는 과제를 중심으로 위버스의 탐색 경로를 살폈습니다. 두 차례 사용성 테스트를 통해 참가자가 어떤 단계에서 멈추고 무엇을 눌렀는지 기록하고, 카테고리와 상세 필터를 사용하는 화면 흐름을 개선했습니다.

A 해결할 문제 카테고리를 고른 뒤에도 남는 탐색 사진 탭에 진입해도 연도와 공연 같은 조건을 좁히는 위치가 바로 보이지 않으면 목록을 다시 훑게 됩니다. 첫 테스트에서는 필터 진입 여부와 목표 게시물을 찾는 과정에서 헤매는 행동을 함께 봤습니다.
B 핵심 개선 카테고리와 상세 조건의 역할 분리 사진·영상처럼 빠르게 바꾸는 분류는 칩으로 두고, 연도·앨범·이벤트 등 여러 조건은 상세 필터에 묶었습니다. 적용한 조건을 확인하고 결과로 돌아가는 흐름이 한 화면에서 이어지도록 설계했습니다.
C 테스트 결과 과제 기준 55%에서 92% 팀 보고서에서 같은 유형의 탐색 과제 성공 점수는 1차 55%, 2차 92%였습니다. 각 테스트의 참가자는 5명이었고, 2차에는 중도 포기 없이 모두 끝까지 과제를 수행했습니다.

03 — 참여 과정 · PROCESS:

기획과 작업 과정

  • 참가자에게 줄 과제와 안내를 정리했습니다

    2024년 롤라팔루자 리허설 포토를 찾아 첫 번째 이미지를 내려받는 시나리오를 만들었습니다. 참가자가 기능 이름을 듣고 바로 답을 찾는 일이 없도록 상황과 목표를 중심으로 안내했습니다.

  • 성공 여부와 망설인 이유를 함께 봤습니다

    과제 수행 경로, 성공 여부와 참가자의 발화·몸짓을 정리하고 시선 히트맵을 읽었습니다. 미디어에 진입한 뒤 게시물을 바로 누르려 했는지, 사진 카테고리와 필터 위치를 스스로 알아챘는지를 구분해 봤습니다.

  • 벤치마킹을 개선 화면으로 옮겼습니다

    위버스와 SBS PLAY의 카테고리·필터 사례를 비교표로 정리했습니다. 팀과 함께 개선 방향을 좁힌 뒤 페이퍼 프로토타입과 AS-IS/TO-BE를 제작해 2차 테스트에서 달라진 탐색 흐름을 확인했습니다.

04 — 회고 · AFTERGLOW:

발견했는지와 사용할 수 있는지는 다릅니다

필터를 눌렀는지보다 그 뒤에 무엇을 했는지가 중요했습니다.

같은 성공이라도 필터를 바로 발견한 사람과 목록을 먼저 훑다가 되돌아온 사람의 경로는 달랐습니다. 성공 점수에 발화와 시선 기록을 같이 놓으니, 무엇을 추가할지보다 기존 기능을 언제 보여주고 적용한 결과를 어떻게 확인시킬지가 먼저 보였습니다.
